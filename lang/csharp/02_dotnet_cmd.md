# dotnet new コマンドでカスタムプロジェクトテンプレートを作成する方法

既存のプロジェクト構成を雛形として再利用したい場合、`dotnet new` コマンドで独自のテンプレートを作成すると非常に便利です。本記事では、カスタムテンプレートを作成・インストールする手順を解説します。

## テンプレート作成の手順

### 1. ベースとなるプロジェクトを作成・準備する
まず、テンプレートの元となるプロジェクトを作成します。既存のプロジェクトを改造しても問題ありません。
*   `.editorconfig` などの設定ファイルもそのまま含めることができます。
*   不要な `bin` や `obj` フォルダは削除しておきます。

### 2. `template.json` を作成する
プロジェクトのルート直下に `.template.config` フォルダを作成し、その中に `template.json` を配置します。このファイルがテンプレートの定義となります。

**記述例:**
```json
{
  "$schema": "http://json.schemastore.org/template",
  "author": "User",
  "classifications": ["WPF", "Test"],
  "name": "Wpf app template",
  "identity": "MyWpfTemplate",
  "shortName": "Wpf-custom",
  "tags": {
    "language": "C#",
    "type": "project"
  },
  "sourceName": "Wpf_test"
}
```

### 3. テンプレートをインストールする
プロジェクトのルートディレクトリで以下のコマンドを実行します。

```bash
dotnet new install .
```

成功すると、以降は `dotnet new Wpf-custom` のように呼び出せるようになります。また、Visual Studio などの IDE においても、新規プロジェクト作成メニューに自動的に表示されます。

## 運用時のポイント・注意点

### 再インストールについて
一度インストールしたテンプレートを更新して再インストールする場合、そのまま実行すると警告が発生して失敗します。その際は `--force` オプションを付与してください。

```bash
dotnet new install . --force
```

### `sourceName` の役割と命名のコツ
`sourceName` は、**プロジェクト生成時に新しいプロジェクト名に自動置換される文字列**を指定する重要な設定です。

*   **自動置換:** プロジェクト内のファイル名やコード内に `sourceName` で指定した文字列が含まれている場合、それがプロジェクト作成時の名前に置換されます。
*   **大文字・小文字の注意:** プロジェクト名や `sourceName` は、先頭を「大文字」にしておくことを推奨します。先頭が小文字だと、置換後のプロジェクト内でも小文字として扱われる可能性があり、命名規則上不自然になることがあるためです。

### 補足
もしゼロからテンプレート用の構成を作りたい場合は、既存のテンプレートをベースにするのが近道です。
例：`dotnet new wpf -o ProjectName` でプロジェクトを作成し、そこから不要なファイルを削って構成を整えてみてください。
